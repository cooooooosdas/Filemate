# B2 岗位证据到学习计划交付

日期：2026-10-02。范围：开发执行计划B2中的“计划建议先预览、用户确认后保存”，接续V2.5求职训练和成长档案。岗位计划合同版本为`career-plan-v1`，应用版本保留`1.3.0a1`，数据库保留v24。本轮在现有工作区本地开发和验收，保留既有改动，未提交、推送、发布或更新安装包。

## 用户影响

1. 求职岗位新增学习建议预览。按每知识点最近有效基础作答、图谱待复习关联和最近相关代码提交列出建议与原证据；新一轮答对会更新建议。未采集作答显示待评测，旧证据标日期，不修改能力画像。
2. 核对后保存到现役学习计划。计划和证据Artifact、操作事件在同一事务新增；同证据丢响应重试只返回原计划及进度。证据已改变时拒绝旧确认，要求重新预览；新建议另存一份，原计划仍保留。
3. 学习页可回看原基础作答、知识点、代码或面试，记录每天进度并下载实际CSV/ICS。岗位页支持撤销恢复计划，保留已完成日期；全部完成后撤销再恢复仍为已完成。

计划最多安排7项、每天建议30分钟。预览显示“本次安排/全部岗位要求”及规则，不把固定时间建议作为实际学习时长，不把任务完成或作答量作为能力达标。词法关联需人工核对。基础题只表示原创固定题作答，面试只提供实际回答的人工回看入口。

## 数据、API与生命周期

复用`study_plans`和`study_plan` Artifact，无新表、无迁移、无模型调用。metadata标记`origin=career_plan`，保存岗位修订及证据指纹；`career_basis`保留原规则和引用。按当前岗位、推荐依据和服务器本地日期计算稳定指纹。同秒作答用持久提交事件序号决定先后，未来作答时间排除。新计划时间带时区，兼容读取旧无时区的SQLite UTC时间。

新增四种操作：

- `GET /api/career/positions/{id}/plan-preview`
- `GET /api/career/positions/{id}/plans`
- `POST /api/career/positions/{id}/plans`，需`confirmed=true`和64位证据指纹。
- `POST /api/career/positions/{id}/plans/{plan_id}/{undo|restore}`，需确认且属于该岗位。

复用身份隔离和求职开关，关闭后21种求职操作返回503。确认缺失/字段异常422、不存在或跨身份/岗位404、过期证据409。已接收的同指纹请求即使岗位修改或计划撤销，仍返回原记录，不自动恢复。普通Artifact PATCH不能覆盖确认的岗位计划。

岗位删除预览新增`learning_plan_count`，确认令牌绑定全部相关计划的内容、状态及完成进度；新计划或进度变化使旧确认失效。确认删除同时清除本岗位生成的计划、进度和私有关联事件，保留其他计划、原资料、图谱、代码、面试和Agent。损坏载荷、进度或metadata保留原字节并标记异常，允许撤销和删除预览，禁止恢复；持久关联使损坏载荷仍可按所属岗位清理。

## 限制、回退与后续依赖

- 规则为可解释的本地训练排序；基础题、词法关联、最近代码引用和面试完成量不能证明职业能力。相关节点可能重合，代码引用沿用最近20条投影；Python/Java代码执行边界保持现状。
- 当前固定最多7项和建议30分钟，不做跨课程资源优化或自动重排现有计划。进一步调整仍需新证据及用户确认；已完成进度只证明任务完成。
- 不自动生成课件、题目、编程结果或面试评分。实际供应商质量、真实学生长期效果及导师校准仍待真实数据。
- 可逐份撤销计划并保留进度，或独立关闭求职模块并保留数据。不要降级数据库；关闭求职模块不会撤销已确认的现役学习计划，用户可继续在学习页读取和完成。
- 后续仍按任务卡推进B2其余证据说明和B3真实评测工具；真人招募、资料授权与导师评分需要团队完成，不由Agent补造。
