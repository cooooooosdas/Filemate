# FileMate 整体审计与高水平创新竞赛发展路线

审计日期：2026-09-05 ｜代码基线：`247194a` ｜对象：FileMate `v1.3.0-alpha`

本报告用于团队内部决策。结论来自代码、隔离诊断、测试和公开资料核查；不代表已经完成修复或已经获得竞赛认可。建议、计划指标与实测结果分别标注。既有 PPT、文书、应用源码均未修改。本轮未访问阿里云控制台，未验证生产域名、线上部署或真实模型质量，也未重新验收 Windows 安装包。

## 1. 总体判断与推荐定位

**FileMate 已具备较丰富的可运行产品基础，适合进入有组织的小范围试用；目前最大的升级空间是学习判断的可靠性、差异化效果证据和可交付性。尚不能按公开多用户服务或已验证教学效果的产品推广。**

建议竞赛正式定位：**FileMate——面向大学生的证据驱动学习工作台**。

建议面向用户的表达：**让每份资料，都走向一次真正学会。**

产品说明：把本地课程资料转为有出处的学习内容，将练习、错题、复习和口头表达串成一条可回看的学习过程，让下一步学习建议能够说明“为什么”。这是一项需要继续验证的产品价值主张，不预先承诺提分或优于所有竞品。

首个重点场景建议收敛为“计算机类课程的考前复习”，以操作系统或数据库课程作为第一轮试点；“竞赛答辩训练”作为第二个展示场景。求职、保研、通用文件管理保留为扩展入口，避免同时面向过多用户任务。

## 3. 优先审计发现

P1 表示应在扩大试用前修复的重要问题；“上线门槛”表示改变使用规模前必须完成，并不表示当前本地个人使用已发生泄露。以下为复现或静态证据，不推算线上事故概率。

### F01 · P1：判题会把错误答案转化为“已掌握”证据

`filemate/study/generator.py:218` 的 check_answer 对填空采用双向子串匹配，对 choice 只比较参考答案首字符。隔离复现：参考“线性表”提交“线”、参考“可靠”提交“不可靠”，均返回 True；将含 AC 的答案作为 choice 输入时，只答 A 也被接受，说明不支持多选时缺少拒绝畸形题目的校验。

`server.py:1517` 将结果送入真实作答持久化，`filemate/execution/storage.py:1465` 的连续正确判定会进一步影响掌握状态。后续画像和学习伙伴即使读取真实记录，记录所代表的掌握结论也可能错误。

建议：单选采用完整选项规范化后等值比较；多选显式建模为集合或明确拒绝；填空使用审核后的同义答案集合，拒绝截断与否定冲突；简答以知识点覆盖和反例为依据，低置信结果标“需复核”。验收先固定否定、单位、部分答案、重复答案等反例集；报告误判正确率，而不只报告总准确率。

### F02 · P1：无命中问答仍继续生成，引用缺少校验

`server.py:2035` 在 matches 为空时保留 context_text 并继续调用 chatbot。隔离诊断得到：召回片段 0、生成方法调用 1、citations 0、success True。这个实验只证明调用路径，不证明真实模型一定幻觉。`filemate/understanding/retrieval.py:129` 只要求词法得分大于 0；零星共同字不能代表有回答依据。

`filemate/understanding/ai_tools.py:421` 直接返回生成文本，缺少引用编号合法性、引用是否支持结论的检查。

建议：先建立可回答／不可回答／材料冲突三类分支。无可靠片段返回明确状态，生成调用次数必须为 0；引用先验证编号和来源版本，再抽样人工核对结论支持关系。不能把检索分数当作概率置信度。将“存在引用”和“引用支持结论”分别统计。

### F03 · P1：面试降级评分偏重字数，历史无法可靠区分评分来源

`filemate/understanding/interview.py:286` 本地回退按字数构造内容、结构、表达和岗位匹配分。隔离诊断中，重复“​​不知道”60 次得到 90 分。`filemate/execution/storage.py:1630` 的 interview_turns 写入包含分数和维度，但未保存 scoring_mode；后续聚合混用不同质量的分数。

建议：模型不可用时保留练习、录像和客观节奏指标，内容质量显示“待评估”；如保留启发式分数，明确命名并单独统计。新增评分来源、规则版本、模型版本、回答证据与复核状态字段；历史旧数据应标“来源未知”，不追溯伪造模式。采用等长度正确／错误／无关回答评测，并由双导师盲评校准。

### F04 · P1：目标反推混用全库统计，任务完成状态可能失效

`server.py:1369` 把全库 learning_analytics 传给选定资料的目标规划；另一门课的练习会影响当前目标的就绪判断。`filemate/study/goal_planner.py:139` 按固定 task_id 继承完成状态。隔离复现：新增 7 道待处理错题后，“复习 7 道待处理错题”仍显示 completed。

建议：以 course/source/goal 关联实际作答、错题和时间窗；任务保存对应证据版本及完成条件。出现新错题或材料变化时重新开启任务，并显示变更理由。考试目标 85 分应作为用户目标，不应由练习次数推断达成。

### F05 · P1：开发和生产代理均有接口遗漏

`filemate/web/vite.config.ts` 列举 AI 路由却遗漏 `/ai/contexts`；本地经 5173 访问实测 404，前端 services/api.ts 又使用该路径恢复会话。

`deploy/Caddyfile:18` 的代理清单遗漏 `/goals*`、`/trust*`、`/agents*`，而后端和 Vite 已有这些路由。按当前配置部署时，这些请求不会转入 API，可能回到静态站点处理。此项为配置确定性缺口，未在真实 ECS 上复现。

建议：短期补齐并覆盖 GET/PATCH/POST/DELETE 的代理合同测试；中期统一 `/api/v1` 命名空间，使浏览器页面与 API 路径不冲突。生产验收必须检查业务响应结构，不能只检查 HTTP 200。

### F06 · 上线门槛：共享站点不是独立个人账户

`server.py:128` 使用进程级共享存储；公开业务路由没有用户身份依赖。`storage.py:90` 等虽有默认 local 工作区，但 API 没有按已认证用户校验对象归属。Caddy 的 Basic Auth 可以限制访问者，却不能在已进入的访问者之间隔离资料、作答和面试记录。

建议：近期采用公开宣传页＋独立桌面应用＋限制访问的匿名演示环境。真实学生各用本地实例，或为试点提供真正隔离的实例。若准备公开注册，需要身份验证、逐对象授权、数据隔离、配额、备份恢复及可复核的访问日志。不要把全校试用直接接到同一份 SQLite。

### F07 · P1：隐私模式名称超出了实际开关作用范围

`server.py:657` 用 FILEMATE_INTERVIEW_LOCAL_ONLY 决定可信中心 mode，但该开关仅控制面试，`/ai/chat` 等仍可创建外部 LLM 客户端。版权声明表提供状态和分享约束，尚不是全链路模型外发授权执行层。

建议：界面明确“仅面试本地评分”或建立全局外发策略；每次外部调用由服务端校验资料使用范围和用户授权，展示将发送哪些数据。云端页面中的“本机”应明确是服务器还是用户电脑。浏览器语音识别的数据路径也应单独说明，不能由“录像不上传”推断所有语音处理都在本地。

### F08 · 创新主张：多 Agent 目前主要是角色目录与过程日志

`filemate/core/trusted_agents.py:26` 是固定路由表；`server.py:1321` 在规划后写入两角色摘要。`list_agent_memories()` 的生产读取目前用于 `server.py:655` 的可信概览，未找到读取长期记忆后改变规划或回答的主链。数据结构和可撤销界面有价值，但不足以证明多角色推理更有效。

建议：对外称“可追踪任务协作”或“角色化处理”。只有在真实执行器、工具输入输出、按角色读取记忆、过期和删除过滤完成后，才进行同模型、同预算的多 Agent 消融。先实现资料检索→学习教练→结果核验三个有必要的角色，角色数量不作为指标。

### F09 · 产品完整性：资料驱动面试和停顿检测需要准确表述

`filemate/understanding/interview.py:193` 在题库不足时才用资料补题；`server.py:2023` 按既定题目顺序前进，尚不是根据本轮回答持续生成个性化追问。`Interview.vue:324` 以语音识别事件到达间隔估计停顿，这会混入识别或网络延迟，不能视为声学静音的准确测量。

建议：保存问题对应的资料片段；依据上一轮回答的遗漏和矛盾生成一次受控追问，设置难度与预算上限。语速作为参考，真实停顿后续接本地音频活动检测；先建立允许人工校正的回放标记。人物表情宜表达鼓励，不把低分转化为惩罚。

### F10 · 工程质量：规模、自动验收和资料生命周期还有缺口

- `server.py:750` 全库搜索仅取最近 100 份资料，逐份加载片段再分词；资料增长后可能漏检旧资料，且请求重复计算索引。优先分页／显式范围、增量索引和查询缓存，再由评测决定是否引入向量检索。
- 多个 async AI 路由直接执行同步模型与解析方法，例如 `server.py:2035`；高延迟工作会阻塞事件循环。优先有界工作线程或后台任务，加状态查询、取消和超时，随后测并发。
- `server.py:765` 的 DELETE 内部计算影响后立即执行；前端仅通用二次确认。文档所称“删除前影响预览”尚不是可由用户查看的独立阶段。应先返回影响清单，再带版本确认；托管文件清理失败时明确结果并支持重试。
- `scripts/acceptance/browser_smoke.mjs:14` 仍列 14 个路由，遗漏 goals/trust；CI 的前端阶段只构建，未自动执行浏览器操作验收。
- `evaluation/run_evaluation.py:61` 生成报告，但没有依据性能阈值或评分失败主动非零退出；指标退化可能仍保持 CI 绿。
- 前端全量注册 Element Plus；大图约 0.49/1.25/2.08 MB。先按需加载组件与图表、优化静态图片编码和显示尺寸，再以冷启动、LCP 和实际下载量验收。
- Tauri 壳、Sidecar 和手动安装包 CI 已存在，不能说“完全没有桌面工程”。但固定 8001 端口、进程启动/退出、录像回放 CSP、干净机器安装/升级/恢复仍需实机矩阵；本轮没有安装包通过证据。

### F11 · 团队治理：现役说明与竞赛名单需要统一

README 尾部仍列徐书和、余恒，与用户确认的五人“胡希、于恒、杨乐、张金宝、汤新阳”不一致；schema 文档存在 v8/v9/v14 三种口径。产品文档还有旧 Logo 的森林绿色描述。

## 4. 多维度优化路径

| 维度 | 可以保留的基础 | 下一阶段目标 | 验收证据 |
|---|---|---|---|
| 产品 | 资料、练习、错题、复习、面试均有入口 | 一门课程从资料到复练一次走通；减少重新上传和页面跳转 | 无人指导任务录像、任务完成率、首次成功时间 |
| 学习可靠性 | 持久化作答和复习状态 | 判题可核对、目标证据分课程、失效状态可更新 | 反例集、错误掌握率、跨课程干扰测试 |
| 检索与引用 | 词法分块、来源与页码 | 大候选库、无依据拒答、逐结论引用 | 固定测试集、支持率、拒答率、p50/p95 延迟 |
| 架构 | Vue/FastAPI/SQLite 和 Provider | 模块化单体、任务执行层、统一 API 合同 | 性能剖析、超时恢复、迁移升级与备份恢复 |
| 创新 | 原资料与派生产物关联 | 可解释学习决策，支持教师复核 | 有／无证据链消融与同任务竞品对照 |
| 面试 | 本地录像、语音输入、评分接口 | 评分来源分离、内容证据、回答驱动追问 | 双导师一致性、MAE、错误回答反例 |
| 个性化 | 学习伙伴由真实行为触发 | 用户可选反馈风格、弱打扰、完成后庆祝 | 7～14 天复习率与可接受性访谈 |
| 发布 | 构建、Sidecar、Docker 配置 | 本地版稳定安装；线上隔离演示 | 干净机器验收、恢复演练、生产合同测试 |
| 研究 | 合成基线和分析工具 | 外部真实语料与独立标注 | 匿名原始记录、协议、置信区间与失败案例 |
| 推广 | 品牌与演示材料基础 | 一个清晰使用场景＋可体验入口 | 激活漏斗、7日闭环完成、试点复用案例 |

架构演进建议：保持模块化单体。先将 server.py 按资料、学习、面试、可信服务拆为路由与业务服务；SQLite 继续承担单用户本地持久化。统一 Source/Artifact/Attempt/Goal 的关联、版本和事件，再扩充后台任务。已有迁移只追加、不重写；当前最高为 v14，后续版本由集成负责人串行分配。仅在公开多人部署需求明确时评估 PostgreSQL 等共享服务，不为竞赛图示先引入微服务或图数据库。

## 5. 竞品参照与真正值得争取的差异

以下依据官方功能资料，查阅于 2026-09-05；未对竞品进行本轮账号内实测。“未核验”不等于“没有”。

| 对照对象 | 已公开能力 | 对 FileMate 的启示 | 建议对照任务 |
|---|---|---|---|
| NotebookLM / Gemini 学习工具 | 来源问答、引用、卡片和测验；学习笔记还提供诊断测验、个性化内容、进度调整 | “能出题”“有学习闭环”本身不足以证明独有 | 同一课程资料，核对答案、错误复练与学习证据的可追溯程度 |
| Notion Enterprise Search | 搜索工作区与连接应用，并附来源引用 | 引用和跨资料搜索属于竞争基础 | 从通知识别任务到完成后的知识复用，记录操作步骤与遗漏 |
| Anki | 间隔重复及 FSRS 选项 | 不将间隔重复当原创算法；重视记忆计划质量 | 同一知识点，在相同复习时间下比较延迟测验表现 |
| 手工文件夹＋通用问答＋日历 | 可灵活组合完成任务 | 是现实中低成本、有说服力的基线 | 完整任务的时间、切换次数、纠错成本和一周后能否找回依据 |

来源：[Google 学习功能](https://blog.google/innovation-and-ai/models-and-research/google-labs/notebooklm-student-features/)、[Gemini 学习笔记](https://support.google.com/gemini/answer/16972047)、[Notion 搜索](https://www.notion.com/help/enterprise-search)、[Anki 算法说明](https://faqs.ankiweb.net/what-spaced-repetition-algorithm.html)。

值得主攻的三个创新机制：

1. **目标相关的学习证据链。** 每个学习建议能展开：哪份资料→哪道题→哪次错误→为什么今天复习→复练后是否改善。用户修改资料、撤销记忆后，派生建议能识别失效。这是具体机制，不是把“可解释”放进宣传词。
2. **可信的学习行动执行。** 把资料整理的预览、确认、冲突保护、撤销，与学习产物版本管理贯通。当前文件执行已有基础，学习建议的影响预览是后续增量。
3. **资料理解到口头表达的连续训练。** 针对同一知识点，完成问答、练习、错因解释和答辩追问；每一次反馈都能回到课程材料。重点验证迁移表达能力，不把摄像头开关当核心创新。

多 Agent 是实现选项，电子伙伴是交互选项；只有帮助上述机制取得可测改进时，才进入核心创新陈述。

## 6. 评测与论文研究转化

建议先完成两项主研究，再拓展面试和伙伴实验。团队现有“30 人、每条件 15 人”是内部采集计划，不能视为统计充分性的保证；根据主指标、预期效应与先导数据做样本量规划。样本不足就报告探索性结果。

### 主实验 A：检索与引用可靠性

- 数据：至少三门课程的授权材料，建立统一候选库，加入相似章节、版本冲突和无关资料；划分开发集和锁定测试集，禁止用测试结果反复调阈值。
- 问题：事实定位、同义改写、跨页综合、材料冲突、无答案。建议先收集 100～150 个真实问题；现有 41 条保留为回归集。
- 标注：两人独立标出“是否可答、支持片段、结论是否被支持”，再保留分歧并裁决。“双人标注”不是给资料命名，而是两个人独立核对同一个问题的证据。
- 对照：相同模型下截断全文、现役词法检索、阈值与引用校验版本；若同义改写确实弱，再加混合检索实验。
- 指标：Recall@1/3/5、MRR、引用支持率、错误引用率、无答案误答率、错误拒答率；记录检索与端到端延迟，报告 p50/p95、样本量和硬件条件。
- 注意：每条主张需支持证据；候选引用命中率不能替代整段答案正确率；不得将两候选集的 Recall@3 当全库能力。

### 主实验 B：证据驱动的复习是否减少重复错误

- 对照：普通静态学习计划与按目标证据更新的计划；两组可用内容和练习时间尽量一致。
- 流程：前测→完成学习任务→即时后测→7 天后延迟测验；试用至少覆盖一次到期复习。
- 主要指标建议预先选“延迟测验正确率”或“重复错题率”之一；次要指标为任务耗时、到期复习完成率、任务切换数和 SUS。
- 控制：按基线水平和课程分层；同一参与者多条题目记录不能冒充独立参与者。交叉设计需顺序平衡并防学习迁移污染。
- 报告：组间差异、效应量和置信区间；保留失败样本及退出情况。既有“提升15%、省时20%”只能是待验证目标，不作为删选结果的门槛。

### 扩展实验

面试：文字训练与“语音＋录像复盘＋针对性追问”对照；两位导师对相同回答盲评，分别报告评分模式的 MAE、相关性和评分者一致性；相关性高不等于评分没有系统偏差。

多 Agent：单流程、角色协作、角色协作但关闭记忆三组；同模型、同工具、相同任务和成本预算，记录质量、耗时、调用数、token 和失败率。先确保记忆真的被消费再比较。

学习伙伴：普通提醒与角色反馈随机或交叉试用 7～14 天；看完成率、返回率、打扰程度，不能用一天体验证明长期坚持。由学生自主关闭，低分反馈以陪伴和具体行动为主。

可形成的研究题目建议：《面向本地课程资料的证据驱动学习工作台：从引用可靠性到复习执行效果》。论文结构为问题与相关工作、系统与证据模型、可靠性机制、实验、失败案例、隐私边界和局限。它首先应是一份扎实的系统研究报告；投稿取决于实验质量与目标刊会要求，不能预先保证录用。

### 三分钟演示主线

- 0:00–0:20：展示同一门课的课件、考试通知和错题，明确任务“十天后考试，我今天该学什么”。
- 0:20–0:45：导入通知，预览分类与日程，确认归档；快速展示可以撤销。
- 0:45–1:15：问一个资料内问题，打开原页核对；再问一个资料外问题，展示拒答。拒答修复前不能伪装演示。
- 1:15–1:50：做错一道题，查看错误解释，进入复习任务，说明这个建议来自哪次错误。
- 1:50–2:20：复练纠正，目标页面说明证据变化和下一步任务。目标隔离修复后再录此流程。
- 2:20–2:45：对同知识点进行简短口头解释，回看一个有证据的反馈。避免全屏只有虚拟人物。
- 2:45–3:00：展示真实评测的样本数和边界；结束语“让每份资料，都走向一次真正学会”。

## 8. 应用推广与可持续运营

### 路径选择

近期优先：**公开产品介绍站＋本地桌面测试版＋授权匿名演示环境**。网站与桌面可共用前端和核心能力，但“用户电脑本地文件”和“服务器文件”是不同边界，不能宣称云端网页能无授权整理电脑文件。移动端继续不投入。

宣传站建议按“面向谁／解决什么／90秒看懂／真实截图／可验证机制／版本与边界／下载与试用／问题反馈”组织。把正式报告和测试基线标日期与版本；下载包提供版本、校验值、安装说明和已知限制。域名是否已可用及备案进度仍需后续部署验收。

### 分阶段增长

第一阶段，5～10 名种子学生在各自环境完成同一课程任务；记录卡在哪一步，目标是首次使用无需开发者陪同。第二阶段，30 名左右真实学生开展规范试点，优先通过课程学习小组、竞赛社团和辅导教师招募。第三阶段，验证其他课程能复用，再讨论院系或学习支持中心试点。

建议北极星指标：**每周完成一次“有来源的练习→纠错→到期复练”的活跃学习者人数／占比**。配合激活率、首次任务耗时、D7 返回率、到期复习完成率与反馈问题率。页面浏览、AI 调用次数和人物点击量只能作为辅助。

商业路径是待验证假设：个人本地基础版；个人增强服务按实际模型成本设计用量；机构试点提供受控部署、内容配置与报告服务。当前不建议凭空设收入规模或给出收费承诺。先访谈学生、教师与实际预算决策者，分别验证使用价值、采购意愿和运维负担。

成本模型：单次有效学习任务成本＝模型与语音实际费用＋服务器和存储分摊＋支持成本；成本日志需记录调用数、token、重试、失败和缓存。月度预算同时列样本量、活跃用户、每用户任务数；单纯服务器年费不能代表产品运营成本。低内存机器先测解析和并发峰值，不再堆叠大模型、向量库和复杂服务。
