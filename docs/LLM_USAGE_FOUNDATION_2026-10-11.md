# AUD-08 用量与调用隔离子卡

当前为本地候选，尚未部署；AUD-08 仍然未关闭，总产品仍为 CONDITIONAL PASS。本子卡修复统一入口丢失真实用量、共享客户端混用上下文、全局注册表缓存请求专属密钥及普通 Agent 线程池缺少上下文继承的问题。账户/全站累计预算、用量持久化、统一 Trace、任务和存储限额继续保留，不用本子卡替代完整审计任务。

## 调用合同

`LLMClient.call()` 和供应商 `chat()` 仍返回纯文本。新增适配层 `chat_with_metadata()` 返回 `LLMResponse(text, model, usage, request_id)`；只实现旧文本接口的适配器仍能使用，其用量保持未知。

`get_usage()` 返回当前请求/线程上下文中，这个客户端最近成功调用的供应商计数。仅接受 `prompt_tokens`、`completion_tokens`、`total_tokens` 中真实返回的非负整数，拒绝布尔、负数、字符串、浮点及过大值。未返回字段省略，`call()`失败及开始新调用时清空旧用量；未知不能显示为零。返回独立副本。成功HTTP回复后若上层结构化解析失败，已知计数仍然保留，不能把解析失败当作供应商没有消耗。该数据暂未写入数据库或展示费用，不能称作已完成计费与配额控制。

模型默认超时和尝试次数读取当前 `LLMConfig`，调用可显式覆盖；尝试次数1–3，输出上限1–65536，超时为0–300秒之间有限值。重试共用递减时间预算，末次429不再额外等待，不在时间预算耗尽后发起新的重试。连接适配器仍使用 Requests，其超时是 socket 无数据等待时间，并非整个下载的硬墙钟上限；慢速持续响应的硬截止/中止依旧待处理，不能据此宣称已具备全调用总超时。见 [Requests 官方超时说明](https://docs.python-requests.org/en/latest/user/quickstart/#timeouts)。

普通线程池每个工作项使用独立 `copy_context().run`，复制请求专属凭据和其他上下文，并保留 worker 间的状态隔离；两处串并行组合入口都覆盖。参照 [Python Context 官方说明](https://docs.python.org/3/library/contextvars.html)。注册表在存在请求专属密钥时创建短生命周期客户端，不更新全局 `_llm` 或 `_config`，避免当前账户密钥成为之后账户的共享默认值。

供应商请求标识仅接受1–128位字母、数字及 `._-`；429错误不回显任意 `Retry-After` 头；统一客户端记录 API 异常类型，重试耗尽消息不拼接供应商原始异常。通用 JSON Schema 校验与所有调用链的日志脱敏仍属于 AUD-09，未在此宣布完成。

## 验证与限制

原 loopback HTTP 基线返回输入7/输出3，但客户端报告0/0，FAIL证据保留。新增合成回归包含实际 HTTP 的成功、无 usage、错误、异常字段，复用客户端的线程/请求上下文隔离，请求密钥缓存隔离，普通 Agent 串并行继承，重试预算、参数拒绝和旧文本适配器兼容。

初次红测试含两项测试类名错误；第一次绿跑42通过/1失败，失败为混合模式测试错误假定结果按添加顺序返回。已修正测试夹具和比较方式，保留原记录；不是将失败证据覆盖为通过。最终专项46通过；默认全量门禁退出0，984后端通过/20跳过/5排除/3告警，51前端及类型、构建、体积通过。完整失败与成功证据见 `docs/audits/llm-usage-2026-10-11`；`raw-logs.json`用Base64保存原始日志字节及SHA256，逐项解码比对通过，避免日志尾空白触发源码检查，不改变原内容。所有新输入均为本地合成资料，未访问外部收费模型、真实账号或学生数据；不能当作真实供应商账单校验或学习效果实验。

源码涉及 `llm_client/client.py`、响应模型、两种供应商合同、`core/registry.py`、`core/agent_coordinator.py`、新增专项测试和验证脚本。没有新增 HTTP 路由、环境变量或数据库迁移；schema仍为26，前端资源不变。公网仍运行既有前端8abeb8a8版本，本地候选不冒称已上线。下一步在本子卡通过后继续累计预算的持久化、隐私导出/删除和备份/回滚边界，再处理完整 AUD-09。
