# 桌面父进程环境隔离验收

任务边界：A5/B3 发布加固，基线 `main` 的 `b65744d09da01adb041acfeb2a722a94013e2018`。不修改业务 API、SQLite migration 或网站环境配置。

## 实际发现

原桌面宿主只固定数据路径和关闭令牌，没有固定运行模式、端口、监听地址、Host 和 CORS。若从携带网站运维环境变量的终端启动桌面，Sidecar 会继承这些值，违反桌面仅在 `127.0.0.1:8001` 提供本地服务的合同。

测试先行提交 `322c271614e7b14aa48577a7df5ecdba0554a104` 的真实 [Windows CI 36982883248](https://github.com/cooooooosdas/Filemate/actions/runs/36982883248) 复现失败：Sidecar 独立冒烟和 NSIS 构建成功，但带入网站配置后的安装版无法通过桌面地址就绪检查。失败机器可读证据保留，未删除失败检查或降低判断条件。

## 修复合同

- 宿主固定回环监听、本地身份、非生产环境、三个本地 Host。
- 发布构建只允许三个 Tauri Origin；debug 构建再允许严格端口 5173 的 Vite Origin。
- 保留既有数据路径和随机关闭令牌；不覆盖模型凭据、功能开关及用户外发同意设置。
- 安装验收限定一次性 Windows CI/虚拟机，已有应用数据目录或占用端口时拒绝开始。
- 验收失败记录 `passed=false`、失败阶段与错误；测试进程结束后恢复其 PATH、代理和环境变量，不修改系统环境。
- 脚本用 UTF-8 BOM 兼容 Windows PowerShell 5；未指定隔离 runner 的本机调用只执行安全拦截，不运行安装或卸载。

## 验收方式与边界

`scripts/smoke_windows_installer.ps1 -VerifyInheritedEnvironment` 在安装版启动前注入网站的监听、端口、生产模式、匿名身份、Host 和 CORS；随后通过真实 TCP 监听、健康接口、匿名 Cookie 缺失和三个 Origin 的 OPTIONS 响应验证桌面边界。继续执行安全凭据库、窗口退出、Sidecar 停止、卸载及数据库文件保留检查。
