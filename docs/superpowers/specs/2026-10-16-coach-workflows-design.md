日期：2026-10-16。状态：已完成独立设计检查，并经用户Q17确认完整设计（含第11节工程取舍）；面试实现计划另行审阅，未开始产品代码实施。

## 1. 目标与边界

让学生容易找到功能，并从一次回答、一次代码错误或一个真实岗位，完成可保存、可重试、可回看的训练。真实学生日常使用与比赛演示同等重要；演示使用明确标记的合成账户和资料，走同一业务流程，不给正式账户植入样本统计。

保留 Vue 3 + TypeScript + Vite、FastAPI、SQLite、Tauri 壳及现役模型／语音／判题适配器。沿用 FileMate 蓝色、LOGO、冰蓝工作台和白色阅读面板。原型 HTML 不直接并入生产站，而是以现有 Vue 页面与组件实现。

顺序为：面试 → 编程 → 岗位与学习资源 → 三条流程联调。每批同时完成失败恢复和任务引导；不等待所有模块做完才形成可用版本。

本轮不更换前端框架，不重写账号、上传和判题沙箱，不扩展 OJ 语言，不加入自动投简历／自动投递、不抓取付费或受限全文、不新建第二套画像。OPT-02～05 的其他原始功能缺项继续留在原账本，不被本轮三页交付冒充完成。

## 5. 面试教练

### 5.1 一题内的完整操作

选择现有训练类型和方向 → 明确本场文字外发授权 → 大字显示当前问题 → 输入／录音转文字 → 提交先持久保存 → 有授权则分析本次文字回答 → 展示引用、问题和改进建议 → 修改重答或进入下一题 → 汇总报告。

未授权仍能保存、继续和看本地采集证据，不伪造内容分数。授权说明列出当前问题、回答、训练方向会发送给已配置的模型服务商；不默认发送录像、照片、整份资料或其他会话。原有知识讲解、本地模式和私有资料限制优先，受限时明确说明。

关闭授权会停止后续自动请求，并使当前未完成分析失去写入资格；不删除原答和旧反馈。授权只属于当前场次，不能自动沿用到下一场。

### 5.2 回答版本与证据

每题保留稳定 `turn_id`，每次提交新增不可变回答版本，绑定 `attempt_id`、顺序、文本摘要、提交时间、分析状态及所引用的问题版本。最后一次提交始终是当前版本，不能用最高分或旧成功结果替代。

分析状态为未请求／分析中／成功／失败／取消。失败、取消或 JSON／原句核验失败时，当前分数为空，显示待分析和重试；首答及历次反馈仅在历史区。当前版本有结果才进入当前报告分数；报告显示已作答题数、已分析题数及不足范围，不把局部均分称为完整整场成绩。

内容观察复用现有六类状态和四个评分维度；肯定判断与评分依据必须能定位到该次回答原句。“未涉及”明确是本题内容观察，不是对学生总体能力的断言。AI 建议标为参考，不写入核心画像当作事实。

新回答使旧报告失效，需重新生成。首末对比保留各自问题、模型、提示词／评分版本与时间；版本不同不能直接宣称量化进步。简历、求职匹配、成长页和跨次记忆消费当前有效版本，引用旧版本时明确其历史身份。

### 5.3 提交、重试与题目推进

- 同一提交键、同一正文重复发送只保存一次；同键不同正文或预期版本变化返回 409，保留本地草稿并给出重读入口。
- 回答先保存，随后分析；浏览器关闭不丢已确认保存的回答。分析不依赖页面内存作为唯一记录。
- 每场最多一个在途分析，通过数据库原子认领保护；重复点击、重连和多标签不重复发起同一次分析。显式重试是新分析运行、可能消耗新配额，不能承诺供应商在请求中断时绝不计费。新提交或取消后，旧分析不得覆盖新版本；旧内容最多作为对应历史版本的结果保留，不改变当前展示。
- “下一题”是显式操作。前端的反馈阅读位置与现役服务端已提交进度分开保存；首次作答沿用现有提交链，重答只新增版本，不再次推进进度。
- 未进入的下一题允许在显式继续时用最后一次真实回答与有效分析更新现有规则追问；已经进入或作答的题目冻结，不能重答旧题时悄悄改写。题库／专项训练的既有规则与题量保留。
- 整场结束后可回看、重答和重新生成报告；不伪造新的训练场次，也不重复创建目标完成事件。
- 模型单次分析最多初次请求加一次格式纠正，总截止 60 秒；网络失败／429不在后台无限重试。实际请求与修正均计入现有配额，失败可由用户重试。

### 5.4 声音与媒体

默认不自动播报反馈。点击朗读调用已配置自然语音，保留晓晓／云夏等现有可用选项；开始输入、录音、切题或切页面即停止音频。语音失败保留文字，不能切换到机械音色冒充成功。

摄像头和录像继续单独主动授权，本地面部动作与表达节奏只描述观测，不能把紧张／开心百分比写成心理结论。媒体原件、采集证据和回答版本各有明确归属，重答不能把前次录像自动挂到新回答。

## 6. 编程教练

### 6.1 真实编译与最小修正

沿用 Monaco、当前 C++17 题库和现有 Windows／Linux 隔离判题，先改善编辑器字号、主题、行号和结果组织。每次评测仍产生新的不可变提交，不覆盖原代码或原判题。

CE 时先展示编译器诊断和行列定位。首批最小修正仅覆盖有明确诊断依据的分号、括号等局部符号问题；开发者限制为最多 3 处、合计 12 个变更行，每处展示前后 3 行上下文。超出范围、改算法／大范围重命名、原因不确定时只给定位和提示。

“原代码／修正建议”是版本对照，不能把右侧提前称为正确答案。建议具有来源、理由、基础代码 SHA-256、题目版本及结构化变更；模型返回的补丁必须通过类型、行号、原片段精确匹配、大小和允许范围检查。

规则能确定的修正留在本地；需要模型时，沿用现有明确外发授权，第一次请求前说明发送本题题面、当前提交代码与编译诊断给已配置模型。不默认上传本地目录、其他文件、隐藏测试或账号信息。

### 6.2 应用、验证与恢复

用户先看差异，再确认“应用并重新评测”；校验编辑器内容仍匹配基础摘要，过期建议返回 409，不能覆盖后续编辑。应用作为一次编辑器事务，保存原始版本和补丁证据；重新评测沿用现役资源、超时、网络隔离和治理配额。

编辑器任一代码变更立即使可见旧结论和待应用补丁失效，历史评测仍可回看。修正后的编译或服务失败依旧可撤销；若应用后又有手工编辑，撤销先预览将恢复的版本并明确确认，取消则保留新代码。正式实现用站内可访问对话框，避免原型中原生确认框的自动化阻塞。

显示“编译通过”或“当前题测试通过”必须引用同一代码摘要、题目版本和真实判题提交，分开展示编译成功与测试通过；不能称算法已普遍正确。未执行、未完成或失败没有通过标记。模型复盘永远不修改判题分数。

WA／TLE／MLE／RE 等先对照真实输入、输出、限制和失败点给提示；不泄露隐藏测试，不自动生成完整解法覆盖用户代码。用户确认练习笔记／复习任务后才保存相关任务；不靠重复点击无限创建。

## 7. 全国岗位与学习资源

### 7.1 官方目录与个人岗位分离

官方目录是公开来源快照，不等于学生已经关注的岗位。用户确认后才加入自己的岗位、选择技能或创建学习计划；联网更新目录不改变个人目标、历史训练或画像。

方向沿用已确认五类，地域全国，默认校招／实习；社招材料另标参考且不计入首批覆盖。每条具体岗位保存企业、官方岗位 ID、职位、地点、就业类型、要求原句、原始 URL、内容指纹、抓取时间与核验时间。每项技能可点回岗位原句，推导映射标待核对。

招聘状态为开放／关闭／未知，与时效分开。只有明确官方状态依据才标开放或关闭；HTTP 200、页面存在或搜索收录不足以证明在招。成功内容核验超过 7 天显示过期；更新失败只更新尝试时间和错误类别，不能改成“刚刚核验成功”，更不能删掉原快照。

岗位更新先保存新快照和差异；个人已保存岗位若变化，显示可核对更新，由用户确认同步。旧训练／报告仍引用旧岗位版本，当前推荐重新计算，不静默改写历史。

**首批覆盖下限是开发者建议，待整体方案确认：**每方向至少 3 个去重的具体校招／实习岗位，合计至少 15 个、至少 3 家企业，交付时均在最近 7 天内成功核对来源内容。状态未知必须保留未知；不能用陈旧社招或合成企业凑数。某方向不足就将该方向覆盖验收保持未通过，其余可独立交付。

### 7.2 主动更新与用户导入

使用可替换的官方来源适配器、已核验快照与固定来源清单，不建设任意 URL 爬虫。先做公开官方页面／公开接口可行性子卡，再固定首批来源；不绕过登录、验证码或访问限制。

用户粘贴链接：支持已接入官方来源时读取，未接入时保存来源链接并引导粘贴原文。用户粘贴描述：复用现有要求提取→原句核对→确认保存链，始终标用户导入，不伪装成官方核验。

更新有持久运行状态和请求幂等键，每空间最多一批在途；浏览器轮询不触发新抓取，重启后中断任务可手动重试。开发者初始限额为每批最多 20 页、总截止 60 秒、单页 10 秒、响应正文最多 2MB、重定向最多 3 次；同来源并发 1、最多每秒 1 次、相同空间／来源冷却 10 分钟。部分成功保留成功快照，并列出未完成项。

服务端只允许已配置来源的 HTTPS 目标；每次 DNS 和重定向均拒绝回环、私网、链路本地、云元数据等非公网目标，防 DNS 重绑定；正常验证 TLS，不转发用户 Cookie、Authorization 或模型密钥。网络出口还受现有部署策略约束。来源失败不影响上传、面试和判题。

### 7.3 资源筛选与计划

每个方向先呈现最相关的 3 个技能，技能来自具体岗位原句；每项技能精选 1–3 份资源，说明适用基础、推荐原因、对应章节／主题、提供者、最近核验时间和链接类型。每个方向至少覆盖文档、书籍信息及一条具体公开视频，不能只放通用搜索链接充数。

链接默认跳转原站；B站采用具体视频的标题、作者、公开地址和适用说明，搜索入口可作为补充并单独标记。书籍仅存元数据与章节建议，不擅自抓取全文。资源失效保留原计划记录并提示替代，不默默用另一门课程覆盖。

选择资源后先预览计划、日期和时长，再确认加入。首批每个学习日关联一项资源，最多 7 项，默认每项 30 分钟、从用户选择的开始日期顺排；复用现有 `study_plans`、`completed_days`、岗位计划事件与当日预算，不另建重复进度表。预览清楚标明哪些在今天、哪些在后续日期；超出今日预算按现有队列规则延后并解释。

外链放独立资源字段，不放进站内 `route`。完成学习是手动自我记录，可取消；打开链接、观看时长或打卡均不自动增加掌握度。原有实际作答、代码提交、面试与错题证据才用于技能覆盖说明。

导入自己的或公开授权的资料时复用统一 `/import` 和 Source；计划关联 Source ID 与版本。既有资料直接选取，不再每页放一组上传控件。删除资料后相关资源链接和证据失效，保留范围遵守现有删除预览与确认合同。

“带着问题去练习”携带岗位 ID、岗位版本、技能和计划来源，进入合适的编程／面试／复习入口。编程目录没有对应题目时明确说明，不把任意 C++ 题标成 Java 或 AI 专项。返回时保留任务位置和原始计划。

## 9. 分批交付与验收

### 批次 A：面试

先完成回答版本、最后一次语义、分析并发与报告证据，再接三步教练界面与语音／媒体停止行为。验收至少覆盖：

1. 首答保存→自动反馈→修改重答→首末原句对比→下一题→报告→刷新后回看。
2. 最后一次失败时分数为空、旧成功只在历史；重试同版不重复保存回答，重复请求键不重放模型，显式新重试按真实调用记账。
3. 双标签提交冲突、迟到分析、关闭授权、删除场次、数据库写失败均不丢旧资料或串版本。
4. 旧会话可读；岗位、成长、简历与记忆不将已失效分析当当前事实；无模型时保留完整文字训练。

### 批次 B：编程

先固定补丁合同与原始代码保护，再完善 Monaco 和差异交互。验收至少覆盖：

1. 缺分号代码产生真实 CE→定位→差异预览→确认应用→真实重新评测→撤销。
2. 修改代码立即撤下旧通过标记；过期／越界／大范围／恶意模型补丁被拒绝。
3. 修正后评测服务失败仍可恢复原版；应用后有新编辑时取消撤销不丢编辑。
4. WA／TLE／MLE／RE 保留真实结果并给适当提示；判题配额、沙箱、取消与租户隔离不退化。

### 批次 C：岗位与资源

先做来源可行性，再做真实目录与受限主动更新，最后接资源计划和训练。验收至少覆盖：

1. 五类、至少 15 个岗位、至少 3 家企业达到上述来源与时间要求；校招／实习／社招参考不混淆。
2. 更新成功、部分失败、过期、明确关闭、来源解析变化和重启中断能区分；旧快照及个人训练仍可用。
3. 自行导入→原句核对→确认，不能伪造官方身份；SSRF、重定向、响应超限及重复更新受限。
4. 每方向有真实精选资源→计划预览→确认→今日安排→手动完成／撤销→对应训练→保留来源返回。
5. 断网、外链失效、资料删除和岗位版本变化有明确恢复办法；不能把搜索入口、打卡或空证据变成技能分数。

### 批次 D：联调与候选发布

使用独立合成账户走“注册登录→导入资料→计划→编程与复盘→面试重答报告→真实岗位与资源计划→成长引用→导出→删除预览确认→备份恢复”。与真人学习效果分别记录，不称合成回归为真实实验。

在 390／768／1280／1440px 检查入口、长问题、长代码、空／加载／错误状态、键盘、减少动态与返回位置。服务端针对版本、并发、治理、外部失败、迁移、恢复和权限做定向测试；每批执行项目默认 verify，发布候选再完成匹配提交的 Linux CI 和真实提供商／编译器检查，不累计不同候选的通过数。

每批给出改动、真实命令和结果、截图、已知限制、关闭方式与对应原账本状态；没有实测的外部服务保持未验收。
