# FileMate 网站评估与优化提示词

**对象**：https://filemate.asia
**日期**：2026-11-04
**方法**：Chromium 无头浏览器实测（1440×900 / 1920×1080 / 390×844 / 375 / 320），冷加载 2 轮取稳定值；PerformanceObserver 采集 FCP / LCP / CLS；直接读取 HTTP 响应头与前端产物；对照 `DESIGN.md`、`PRODUCT.md` 与 `filemate/web` 源码。
**未覆盖**：登录后带数据的页面（需真实账号）、跨地域 TTFB、真实用户 INP、屏幕阅读器实测。

## 一、结论速览

整体判断：**这是一个视觉底子扎实、工程素养不差，但"对外"还没做完的测试版产品站。**
视觉系统是自洽的（深蓝 + 钴蓝 + 冰蓝，没有 AI 紫粉渐变，文案有中文语感），基础工程（CSP / HSTS / immutable 缓存 / 焦点环 / 响应式不溢出）也在线。
真正拖后腿的是三件事：**两张大图吃掉 91% 流量、整页级布局偏移（移动端 CLS 0.92）、以及冷访客打开首页后完全不知道这是什么。**

| 维度 | 评分 | 一句话依据 |
|---|---|---|
| 视觉设计 | 7.5 / 10 | 系统自洽、克制；宽屏与空状态排版失分 |
| 用户体验 | 6.5 / 10 | 空状态与隐私说明很诚实；入口过载、侧栏裁切、404 空白 |
| 内容结构 | 6.5 / 10 | 文案有温度；缺价值主张页、信息重复、开发痕迹外露 |
| 性能 | 5.5 / 10 | TTFB 31–154ms、JS 仅 149KB，但总重 1.91MB、CLS 不合格 |
| 工程 / SEO | 4.5 / 10 | 安全头齐全；所有未知路径返回 200、无 robots/sitemap/OG |
| 可访问性 | 7.5 / 10 | 跳转链接、可见焦点、单 H1、触控区合格；禁用态与 12px 文本需修 |
| **综合** | **6.3 / 10** | 骨架好，首屏与"对外表达"没做完 |

## 三、视觉设计

**做得好的**

- 配色克制且成体系：`#14243E` 深蓝侧栏、`#254BC3` 钴蓝动作色、`#C1CDDD` 冰蓝画布、`#16243B` 正文墨色。没有紫粉渐变、没有通用机器人/大脑视觉，和 `DESIGN.md` 的承诺一致。
- 层级靠留白和色块而非阴影堆叠，卡片圆角 14–16px 统一，页面看起来"整"。
- 中文字号梯度清楚：H1 66px（clamp）、模块 24px、正文 17px、说明 15px；行高 1.75 对长文友好。
- 登录页左深蓝品牌区 + 右浅色表单的二分构图是全场最好看的一屏。

**扣分的**

1. **宽屏失守**：1920px 下正文仍贴左，右侧近 900px 纯空白（`/trust` 最明显）。缺少居中的 max-width 容器（建议正文 720px、工作区 1280–1440px）。
2. **空状态排版松散**：首页"归档处理记录"整行铺开、只有两行字；`/ai-tools` 空状态在约 500px 高的面板里垂直居中，CTA 几乎贴到面板底边。
3. **同屏三种按钮形态**：移动端头部是"实心钴蓝方图标 + 裸人像图标 + 白色大圆角方块"，视觉重量不统一，主次不明。
4. **细节不一致**：`theme-color` 写的是 `#f4f8f7`（偏绿白），画布实际是 `#C1CDDD`；手机状态栏染色会跳。
5. **移动端英雄区过重**：571px ≈ 首屏 2/3，其中"一言"占约 230px，第一张功能卡只剩标题露头。

## 四、用户体验

**做得好的**

- 空状态不是"暂无数据"，而是解释"这里将出现什么 + 下一步去哪"（`添加资料后即可读原文…`），对测试版很关键。
- 隐私边界讲得具体到可验证：匿名空间 90 天未使用清理、恢复预览 15 分钟、导入与阅读不调用模型。这在国内学生产品里少见。
- 键盘可达：`Ctrl K` 全局查找、跳转主内容的 skip link、`aria-current` 标记当前项、焦点环 `2px solid #254BC3` 可见。
- 375 / 320 宽无横向溢出，侧栏在窄屏改为抽屉，没有简单缩放桌面布局。

**扣分的**

1. **侧栏在主流笔记本高度下被裁**：1440×900 时 `.nav-groups` 内容高 844px、可视高 694px，底部约 150px（成长记录 / 可信与隐私）藏在状态栏后，且没有滚动条或渐隐提示。
2. **首屏入口过载**：整页 35 个可聚焦控件；"开始学习""这次想做什么（3 组 × 3 子入口）""今日行动"三条主路径并行，新用户不知道先点哪个。
3. **未知路径是空白页**：`/this-page-does-not-exist` 返回 200，页面只剩侧栏 + 页脚，标题还写着"学习工作台"。用户拼错链接后看到的是"坏了"而不是"走错了"。
4. **禁用态骗人**：`读取所选范围` 禁用时仅 `opacity: 0.65`，看起来仍像可点的主按钮；对比真正的次要按钮又不一致。
5. **登录页默认勾选"保持登录 30 天"**：公开体验环境 + 可能共用设备，安全默认值应该是关。

## 五、内容结构

**做得好的**

- 文案有中文节奏，不像翻译腔："今天，让知识成形。""绝望的人没有故乡。""先选一个目标，再决定今天的一步。"
- 每个功能页都有一句"这一页是干什么的"副标题，降低理解成本。
- 状态诚实：无数据显示"待评测"，页脚明写"公开体验环境，请勿上传敏感或未经授权的资料"。

**扣分的**

1. **没有面向冷访客的第一屏**：首页直接是空工作台。没有一句话价值主张、没有产品截图/演示、没有"三步上手"，也没有"游客可试"的引导。评委或同学第一次打开，只能靠侧栏猜这是什么。
2. **信息重复**：`/import` 页"导入后可以做什么"出现两次（右侧深色栏 + 拖拽区下方三步说明）；隐私说明在卡片、右栏、页脚各讲一遍。
3. **开发痕迹外露**：侧栏底部常驻 `v1.3 α4` 与 `服务已连接`，`公开体验环境` 声明却放在页脚最末——优先级反了。
4. **法律/隐私文本抢占主视觉**：`/import` 首屏左侧最大的一块是 4 行隐私条款，把"选文件"这个真正的动作压到第二屏。

## 六、性能与工程

**做得好的**

- 服务端反应快：TTFB 31–154ms，openresty + gzip + 一年 immutable 缓存。
- JS 总量克制：149KB（gzip）/ 19 个分块，没有塞入重型组件库整包。
- 安全头齐全，无控制台报错，无失败请求。

**扣分的**

1. **两张大图 = 91% 流量**（见上表）。手机 4G 下这两张图要等 2–3 秒，且吉祥物只是 110×147 的装饰。
2. **CLS 是硬伤**：桌面 0.394、移动 0.915，两次测量稳定复现。位移源集中在 `.content-scroll`（单次 0.376 / 0.915），根因是异步数据到达前后页面高度不一致——"正在读取你的学习记录…"占位块塌陷、导航 loading 条插入又移除（`.navigation-loading` 让内容整体下移约 36px）。
3. **LCP 比 FCP 晚 0.84s**：首屏 HTML 是空壳，H1 要等 Vue 挂载 + 路由分包 + `me` 请求才出现。预渲染首屏能把 LCP 压到 0.6s 内。
4. **19 个 `modulepreload`**：对一个 2KB 的 HTML 偏多，首屏并发拉 19 个 JS 分块，分块粒度偏碎。
5. **SEO 基础缺失**：无 `robots.txt`（被 SPA fallback 吞成 HTML）、无 `sitemap.xml`、无 `og:` / `twitter:` / `canonical` / JSON-LD。分享到微信/QQ 没有卡片。
6. 只开 gzip，未开 brotli（大约还能再省 10–15%）。

## 七、优先级建议

| 优先级 | 事项 | 预期收益 |
|---|---|---|
| P0 | 图片瘦身（WebP/SVG + 按显示尺寸出图） | 1.91MB → 约 0.25MB，移动端首屏快 2s+ |
| P0 | 消除 CLS（占位同高、loading 不占流） | CLS 0.92 → < 0.05 |
| P0 | 404 兜底 + robots/sitemap | 消除软 404，可被正常收录 |
| P0 | 首屏给冷访客一句话价值主张 | 首次访问留存与理解成本 |
| P1 | 首屏入口收敛为 1 主 3 辅 | 决策成本下降 |
| P1 | 侧栏溢出与层级修复 | 底部 3 个功能不再被藏 |
| P1 | 宽屏 max-width + 空状态重排 | 大屏不再"半张纸" |
| P1 | 移动端头部统一 + 英雄区压缩 | 首屏留出功能位 |
| P2 | OG / 预渲染 / brotli | 分享与搜索表现 |
| P2 | 文案去重、清理开发痕迹 | 专业感 |

## 八、可直接使用的优化提示词

> 用法：把每条提示词整段粘贴给 Claude Code / Codex / Cursor 等编码助手，工作目录设为 `filemate/web`（或整个 `FileMate-Project`）。
> 每条都带了实测证据、硬约束和验收标准，目的是让助手**不要顺手重做设计**，只解决指定问题。
> 若助手有终端权限，最后一步让它自己跑验收命令。

### 提示词 1 · 首屏体积瘦身（P0）

```
你是 FileMate 的前端性能工程师。工作目录：filemate/web。

实测现状：
- 首页冷加载传输 1.91 MB，其中图片 1.74 MB，占 91%。
- src/assets/filemate-mascot.png 1.2 MB（1121×1494），在 Home.vue 里只显示 110×147。
- src/assets/filemate-brand-lockup.png 481 KB（1867×526），在 Logo.vue 里只显示 151×43。
- src/assets/filemate-mascot-expressions.png 2.0 MB、filemate-app-icon-light.png 862 KB 也偏大。

目标：首页冷加载总传输 ≤ 400 KB，图片总量 ≤ 120 KB，视觉观感（清晰度、透明边缘、色准）不得下降。

要做：
1. Logo 改为 SVG（从现有 PNG 重绘或导出矢量），在 151×43 与 216×61 两个尺寸下都清晰；保留原 alt 文案与宽高比。
2. 吉祥物按 "显示尺寸 × 2" 导出 WebP（约 220×294），单张 ≤ 25 KB；同时保留 PNG 作为 <picture> 的兜底。
3. 在代码里显式写死 width/height（用真实像素，不要沿用 1086×1448 这种源尺寸），避免布局位移。
4. mascot-expressions 与 app-icon-light 同样处理：若只在局部使用，改为按尺寸导出并懒加载。
5. 生成一次体积对比表（改前/改后，逐文件字节数），写进提交说明。

不要做：
- 不要改配色、字体栈、卡片圆角、栅格间距。
- 不要把吉祥物换成插画或删掉。
- 不要引入新的图片 CDN 或第三方服务。

验收：
- 首页 network 面板传输总量 ≤ 400 KB；
- Lighthouse "Properly size images" 与 "Serve images in modern formats" 两项通过；
- 1440×900 与 390×844 两张截图中，Logo 与吉祥物无可见模糊或锯齿。
```

### 提示词 2 · 消除布局偏移（P0）

```
你是 FileMate 的前端工程师，负责修复 CLS。

实测现状（Chromium，冷加载，5s 窗口）：
- 桌面 1440×900 CLS = 0.394，移动 390×844 CLS = 0.915（两次复现 0.915 / 0.948）。
- LayoutShift 的 source 是 DIV.content-scroll（单次 0.376 / 0.915）与 FOOTER.site-footer（0.018）。
- 现象：首屏先渲染"正在读取你的学习记录…"占位块与 .navigation-loading 导航条，数据到达后占位块塌陷、导航条移除，整页内容上下跳动数百像素。
- 位移发生在 2.1s 左右，正好是用户开始点击"开始学习"的时刻。

目标：桌面与移动 CLS 均 < 0.05（P75），且首屏不出现"先撑开再塌陷"。

要做：
1. 用骨架屏替代文字型占位：占位容器的高度必须与最终内容高度一致（用 min-height 或 aspect-ratio 锁定），数据到达只替换内容、不改变高度。
2. .navigation-loading 改为 absolute/fixed 覆盖层或固定在预留槽位内，不参与文档流（现在它让内容整体下移约 36px）。
3. 侧栏状态、账户按钮等异步态，预留固定宽高，避免图标/文案切换引起重排。
4. 页脚在数据未就绪时也保持最终高度（不要先不渲染再插入）。
5. 在 Home.vue / App.vue 里检查所有 v-if 切换的区块，逐一确认"有无内容时高度一致"。

不要做：
- 不要用 `transform: translate` 伪装（CLS 只是被掩盖，滚动仍会跳）。
- 不要延迟渲染整页来规避位移。
- 不要改动页面结构与视觉层级。

验收：
- 写一个 Playwright 脚本，分别在 1440×900 与 390×844 冷加载首页，用 PerformanceObserver 累计 layout-shift，打印 CLS；桌面与移动均 < 0.05。
- 连续跑 3 次结果稳定。
```

### 提示词 3 · 404 与路由兜底（P0）

```
你是 FileMate 的前端工程师。工作目录：filemate/web。

实测现状：
- 访问 https://filemate.asia/this-page-does-not-exist 返回 HTTP 200，页面只剩侧栏与页脚，正文空白，标题仍是"学习工作台 · FileMate"。
- /robots.txt 与 /sitemap.xml 也被 SPA fallback 返回 index.html（content-type: text/html）。
- src/router/index.ts 里没有 catch-all 路由。

目标：任何未知路径都有明确的"走错了"页面，并给出回到主线的路径；爬虫拿到正确的 404 语义。

要做：
1. 在 router 增加 `{ path: '/:pathMatch(.*)*', name: 'NotFound', component: NotFound.vue }`，放在路由表最后。
2. 新建 views/NotFound.vue：说明"这个地址不存在或已移动"，提供两个出口（回学习工作台 / 打开今日行动），沿用现有卡片与按钮样式，不新造视觉。
3. 页面标题设为"页面不存在 · FileMate"。
4. 服务端：让 nginx 对静态文件类路径（如 /robots.txt、/sitemap.xml）返回真实文件，不要落到 index.html；对已知的 SPA 路由继续回退。
5. 增加 public/robots.txt（允许抓取，声明 sitemap 地址）与 public/sitemap.xml（先只放 /、/login、/register、/trust 这几个公开页）。

不要做：
- 不要自动跳转到首页（用户会以为链接生效了）。
- 不要为 404 页引入新插画。

验收：
- 手工访问 /abc、/foo/bar 均显示 404 页，标题正确，两个出口可点；
- `curl -I https://filemate.asia/robots.txt` 返回 text/plain 且内容正确；
- `curl -I https://filemate.asia/sitemap.xml` 返回 application/xml。
```

### 提示词 4 · 给冷访客的第一屏（P0）

```
你是 FileMate 的产品设计师 + 前端工程师。工作目录：filemate/web。

现状：
- https://filemate.asia 对未登录访客直接展示空工作台：一句话"今天，让知识成形。"+ "开始学习" + 三个导流卡片 + 空状态。
- 没有任何地方说明 FileMate 是什么、为谁做、解决什么问题；首屏 35 个可聚焦控件、3 条并行主路径。
- 产品定位（PRODUCT.md）：把课件、作业、考试通知沉淀为可追溯的学习资产，形成"理解—练习—错因—计划—验证"闭环；差异化是"AI 建议回到你自己的资料与证据"。

目标：未登录访客 5 秒内知道"这是什么、能帮我干什么、现在点哪里"。

要做：
1. 仅对**未登录且无本地资料**的访客，在首页英雄区下方插入一条"首次到访"引导带（登录后或已有资料时不出现，DOM 也不要渲染）。
2. 引导带内容控制在一屏内：
   - 一句话定位（≤ 22 字，围绕"把课件变成可追问、可练习、可复习的学习资产"）；
   - 三步说明（导入资料 → 提问/做笔记 → 练习与错因），每步一句话，配现有图标，不新画插画；
```
