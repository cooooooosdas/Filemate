# FileMate 试行版整合设计

日期为2026-11-06。用户要求并行完成自有 CampusOS 学习管理助手的借鉴整合，以及学习教练D级验收，汇总截至本轮的增量后发布试行版。用户随后确认按大学生日常学习、现有今日行动与教练流程选择整合能力，并补充左上角LOGO需清晰、融入导航背景。

## 现状与选择依据

FileMate采用Vue3、FastAPI、SQLite，生产Web185f7b3、API fdf6f40。当前源码包含已经批准实施的D级任务1—8，以及de1ba77中的任务9工具。D级专项证据、报告及生产启用尚待收口。2026-11-05最终网页归档提交8e7710a的CI现已成功。

CampusOS路径为`D:/竞赛/campus-os/app-dec6rp0t03r5`，采用React、Supabase与Edge Functions。源码显示资料、练习、错题、简历、目标和计划与FileMate重叠。可借鉴的产品表达集中在目标阶段、依据与偏差说明、周复盘、确认后调整，以及试用反馈。其机会推荐含模型自报核验与固定分数范围，番茄钟跨日统计和会话恢复不完整，计划恢复由多次远程写入组成。本轮选择下列增量，全部通过FileMate现有数据与写入合同实现。

1. 目标行动分为准备、练习、复盘及其他行动，沿用原任务ID、完成状态与入口。显示实际任务数量、截止日期及逾期待办，阶段属于界面组织规则。
2. 今日行动提供按需打开的本周安排复盘。按上海自然周读取当前目标已保存的本周安排，逐项说明当前完成、待完成、失效或无法核对的情况。保存用户复盘后，可带入D教练，由既有方案预览、确认、恢复与撤销承担计划调整。
3. 增加试用问题与建议入口。用户核对类型、模块、描述及版本后提交，保存于自己的学习空间，可以查看、导出和预览确认删除。记录类型与现有相关性评分分别统计。
4. 导航LOGO使用保留原标志与字标的透明矢量派生版，移除独立底块及过小副标题。登录等场景继续使用适合其尺寸的品牌组合。原始素材保留。

以上整合选择由实施者提出，供用户核对。完整五层目标树、长期记忆编辑与禁记、机会抓取、专注会话属于后续候选，评估报告说明现状、依赖与引入成本。

## 本周复盘的数据合同

每次读取必须给出当前明确的`ScopeRequest`，复用现役`resolve_scope`、`SnapshotReader`和`project_tasks`。单个只读快照内，读取该周开始至今天最多7个确定日期的`learning_orchestration_day` Artifact，过滤到同一目标及相同课程/资料范围。重复任务按task_id归并。完成情况采用当前原领域状态，页面标题说明这是截至读取时的本周已保存安排状态。

任务正文从当前授权范围读取。不存在或失效的引用单列为待核对，不能计入完成数。尚未确认的草稿不进入周统计。未保存安排时展示真实空态，并允许记录用户反思。预计分钟只用作安排预算。接口返回周起止、as_of、study_date、scope、snapshot_revision、计划日期数、去重任务数、完成数、待办数、失效数、逾期待办，以及有界的任务展示项和coverage说明。返回任务最多200条，截断必须显式报告。七日记录读取采用稳定日期ID，当前目标证据只组装一次。

保存复盘请求含`scope`、`expected_revision`、`request_key`、`confirmed=true`、用户选定原因和不超过2000字的反思。保存前重新读取并校验revision，变化返回409。持久化内容仅含用户填写的反思、周范围、目标ID、读取时的汇总及规则版本，任务原文留在来源模块。用户原因属于自述，页面明确标识。每个确认生成不可变的`weekly_reflection` Artifact，重放原键返回原记录，同键异内容409。

从已保存复盘进入教练时，保留原今日行动草稿。教练问题加入用户主动选定的反思，并使用`next_step`意图。CoachInput增加可空的reflection_id，服务端核对记录属于同一目标及范围，将该ID与记录摘要纳入教练修订号及依赖元信息。删除复盘的预览展示相关教练结果与派生计划影响，确认后复用现役invalidate_coach_dependencies清除相应派生正文。模型外发继续由D界面的逐次授权与确切上下文预览控制。该入口自身不发起模型调用。教练的范围、任务上限、日期、预算、联合确认及撤销规则沿用D合同。

## 试用反馈的数据合同

反馈分类为bug、suggestion、other，模块来自固定枚举。描述20—2000字，复现步骤不超过2000字，版本来自服务版本及前端构建标识。页面展示填写内容预览，确认提交后写入`trial_feedback` Artifact。记录附`request_key`及内容摘要，单空间单日最多10条新的反馈，重放不重复计数。同键异内容409。客户端不会收集模型密钥、文件正文、摄像头或代码。使用者输入的描述为私人空间内容，用户主动导出后可用于试用问题整理。

保存请求另写无正文的trial_record_request Artifact墓碑，包含类型、请求键摘要、内容摘要、记录ID、创建日期和deleted终态。记录与墓碑原子提交，删除正文与标记终态同事务。恢复查询返回saved或deleted，已删除原键返回410且无法重建正文，同键异内容409。每日10条计数包括已经删除的新反馈。墓碑随个人备份恢复，恢复后的客户端沿用现役epoch清除旧请求定位符。

反馈和复盘的列表限20，最大50，offset不超过10000。列表只读摘要，详情按需获取。按类型过滤，所有访问使用当前租户的SQLiteStorage。删除先预览，使用现役data_actions令牌、内容摘要、confirmed严格true和完成回执实现幂等删除。个人备份、导出、注销与恢复沿用Artifact存储能力。恢复后旧删除令牌必须失效。新模块开关为`FILEMATE_ENABLE_TRIAL_WORKSPACE`及`VITE_ENABLE_TRIAL_WORKSPACE`，默认关闭，正式试行版验收后打开。关闭时仍允许已有记录读取、导出和删除，新建与新复盘读取返回明确关闭状态。

## 界面与运行要求

保持现有四主题、蓝色与无衬线字体，正文至少17px，动作至少44px。本周复盘和反馈界面均懒加载。今日行动增加一处复盘入口，反馈从设置“关于”与成长页按需进入，不新增常驻业务导航。面板使用标题、事实卡片、明确主动作，详细依据按需展开。

切换账号、当前目标或资料范围时清空旧内容与授权。未保存输入离开有提示，迟到响应按generation忽略。响应不明时保留原request_key，通过只读查询恢复，恢复过程不重发写请求。存储定位符只有类型和请求键，正文不进入localStorage。网络失败保留输入，错误可以重试读取。保存成功后显示记录时间及查看/删除入口。

LOGO在展开侧栏、折叠、手机导航及四主题下验证，保持原标志辨识度，确保正文与图形对比清晰。新能力保持143360B初始JavaScript gzip门限，桌面与320/390px下无横向溢出。
