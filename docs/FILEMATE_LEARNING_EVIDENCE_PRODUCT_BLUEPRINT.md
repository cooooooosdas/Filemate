# FileMate 长期产品蓝图：学习证据驱动的个人 AI 助手

状态：产品与技术方向，2026-09-27。本文描述长期路线，只有“首段落地”明确列为现役实现；其余须按验收结果逐步交付。FileMate 是持续开发的产品，竞赛材料从同一产品和证据库派生。

## 1. 服务谁、解决什么

首要用户是需要在一门课程中持续理解、练习、纠错并能口头解释知识的大学生。竞赛答辩、求职面试和保研复试复用同一套“从资料到表达”的训练机制。核心任务是回答三个问题：我目前真正会什么；今天最该练什么；怎样证明我比上次讲得更清楚。

产品主张：**让每份资料走向一次可验证的学会。** FileMate 读取用户授权的本地资料，保存作答与复习证据，提出有依据的下一步行动，并用口头讲解或情境问答验证知识能否迁移。资料变更、评分来源或样本不足必须明确呈现，不能把模型意见写成已掌握事实。

## 2. 产品主链

```text
资料导入与授权
  → 带来源的知识点和题目
  → 作答、错因和到期复习
  → 目标相关的训练任务
  → 不看答案的口头讲解／面试追问
  → 回看原回答、来源与新一轮行动
```

入口围绕课程目标组织，而非按模型能力堆按钮。用户创建目标后，首页显示一个今天可完成的任务、推荐依据、预计所需时间和完成后的证据。允许用户拒绝或改排建议；真正的文件操作仍先预览、确认，支持撤销。

## 3. 六角色按需协作

| 角色 | 真实输入与输出 | 校验边界 |
| --- | --- | --- |
| 资料 Agent | 在已授权资料中定位片段，返回 source、chunk、页码和版本 | 无可靠引用时返回“未找到依据” |
| 规划 Agent | 读取目标、期限与该目标范围内的记录，生成候选训练顺序 | 不用其他课程的统计冒充当前进度 |
| 学习教练 Agent | 从具体错误、复练间隔和任务负担中选一个下一步 | 建议附记录 ID、原因和失效条件 |
| 面试 Agent | 按场景与薄弱点组织首题及追问 | 不把参考答案放进题目，不评价容貌或性格 |
| 评价 Agent | 分别给出客观节奏、内容证据、未知项和改进建议 | 模型不可用时内容“待评估”；不凭语速推断知识掌握 |
| 安全 Agent | 检查资料授权、外发范围、文件影响和记忆撤销 | 未授权内容不外发；高影响动作须用户确认 |

“协作”要求前一角色的结构化输出被后一角色实际消费。Agent 轨迹记录角色、输入引用 ID、输出摘要、模型或规则版本和失败原因；只有真实执行过的角色才出现在时间线。角色数不是产品价值指标，增加角色须证明质量或效率收益。

## 4. 数据与可信边界

统一证据引用使用 `source_id`、资料版本、`artifact_id`、题目序号、`attempt_id`、`wrong_id`、复习事件、`interview_id` 与回答序号。建议和评分保存为派生产物，保留生成时间、方法和适用范围。删除或替换来源时，关联建议标记失效或随资料删除；历史记录不静默改写。

“掌握”必须由同一知识点的复练和延迟验证支持。口头训练的完成只证明用户做过表达练习；在没有经校准的内容评估前，不自动提升掌握度。学习伙伴可以反映真实完成事件和下一步任务，不能用连续签到或虚构成长值代表能力。

默认本地存储。外部模型调用前按资料权利和用途检查可发送范围；录音录像须单独授权，默认不长期保存。可以查看、导出、撤销学习记忆。

## 5. 首段落地：错题到口头解释

本阶段沿用现有 SQLite 表和 Artifact，不新增迁移：目标计划只从所选资料的待纠错题中选一条，添加“口头解释”任务；点击任务打开同一资料的训练页，面试 Agent 用题干组织首题且不揭示答案。后端校验错题属于所选资料且尚未掌握，训练记录和 Agent 运行轨迹保留来源与目标 ID。完成整场训练后，仅把该目标的口头解释任务记为完成，用户可返回目标页查看并重新规划；错题仍须通过实际复练才算掌握。知识讲解暂只保存回答与可选的语音节奏证据，内容准确性标为待评估，不外发题干或回答。

这只是 A＋B 主链的第一段。后续第二轮已补充资料范围内知识点标识和可修正错因；自动追问质量校准、口头表达与原文的逐结论对齐，以及经真人验证的学习收益仍未完成，不能写成现役能力。

## 6. 后续阶段与完成条件

| 阶段 | 可交付用户能力 | 完成条件 |
| --- | --- | --- |
| 二：稳定证据单元 | 同一知识点关联资料片段、题目、错因、复练和讲解；资料改版后指出哪些建议需重算 | 跨课程数据隔离、来源删除、旧建议失效和恢复测试通过 |
| 三：自适应教练 | 依据错因、到期时间和可用时长安排每日任务；用户可改排并看到原因 | 与静态计划在相同资料和学习时间下对照；报告重复错误率与延迟测验 |
| 四：表达养成 | 同一知识点首答、针对性追问、复答、回看变化；伙伴给出可关闭的轻量提示 | 双导师盲评、评分来源与误差报告；7～14 天试用观察打扰程度 |
| 五：产品化 | 安装、备份恢复、数据导出、版本升级、无账号本地使用和获授权的试点 | 干净机器验收、隐私检查、真实试点记录与可复现演示 |

每阶段同时维护功能验收、失败案例、成本和使用证据。小型合成集只作为工程回归；真实用户效果需按 `docs/REAL_USER_EVALUATION_PROTOCOL.md` 单独采集和报告。

### 阶段二第一轮推进（2026-09-27）

已把口头训练任务从“只指向错题”升级为可核对的题目级证据单元：保存来源资料、练习产物、题号、失败作答 ID、作答时间、题目内容指纹和资料内容指纹。目标读取、手动完成、训练启动和训练完成都会重新校验这些引用；出现新失败作答、资料或题目变更、错题已掌握时，旧任务显示失效原因并阻止继续使用。重新规划生成最新任务，同时在 `invalidated_tasks` 留下旧建议及失效时间。来源删除仍按现有外键级联删除其目标、作答和错题，并有回归测试覆盖。

第一轮仍是题目级证据，未处理知识点身份、错因结构化和来源片段引用。

### 阶段二第二轮推进（2026-09-27）

练习题已有的 `knowledge_point` 现被映射为资料范围内稳定的 `knowledge_key`，同一资料内同标签题目可以聚合，不同课程保持隔离；旧题缺少标签时使用题目已有信息形成兼容标识。错题新增七类结构化错因：待确认、概念缺口、记忆遗漏、推理断点、表达困难、选项混淆和审题疏漏。系统仅以本地规则提供低置信度建议，错题页显示来源和置信度，用户可修正并补充说明，用户结论不会被后续规则覆盖。

规划 Agent 会按错因生成不同训练动作，并把知识点和诊断指纹交给学习教练；面试 Agent 再据此切换首题的讲解结构，例如定义与边界、逐步推理或结论—依据—例子。用户修正错因后，旧训练显示失效并要求重排，避免继续执行不适用的建议。Agent 轨迹只保存知识点 ID、错因枚举和作答 ID，不复制答案正文。v16 迁移、跨课程隔离、用户诊断持久化和目标重排均有回归测试。

### 阶段二第三轮推进（2026-09-29）

口头复练任务现会在同一资料的持久化分块中执行本地词法检索，将最相关片段的 `chunk_id`、页码、顺序、检索方法和内容指纹写入 `source_evidence`。目标页和面试页展示可核对位置；规划 Agent、学习教练 Agent 与面试 Agent 仅传递引用 ID，不复制原文或答案。没有可靠词法重叠时明确标记“未找到可靠片段”，不会虚构引用；片段替换、删除或跨资料错配会使旧训练失效。成功定位、无匹配回退和片段变更均有后端回归测试。

当前知识点稳定性限定在单份资料及其持久化题目标签内，片段定位仍是词法匹配，还没有跨资料语义合并、知识点层级关系、语义检索质量评测和人工合并工具，因此阶段二整体状态仍为进行中。

### 阶段三第一轮推进（2026-09-29）

现役“今日学习”从固定排序扩展为本地自适应教练：读取计划日期、到期错题、错误次数和已确认错因，生成每项任务的原因与建议动作；用户可以设定当日 10–240 分钟可用时长，并手动上移、下移任务。预算和顺序按日期存入 SQLite v19，刷新后可恢复；队列只纳入预算内可完成的任务，并显示暂缓数量。系统规则给出的错因继续标为“待核对”，不冒充用户确认或学习成效。下一步需要在相同资料、时间与任务集下和固定排序做对照，并观察延迟测验与重复错误率；真实收益尚待评测。

## 7. 可复用的竞赛证据包

产品维护一套版本化事实清单：功能演示、源码和测试、评测数据边界、用户研究、团队实际贡献、知识产权及财务材料。不同比赛只调整叙述重点和格式：技术竞赛突出可信执行与 Agent 协作，创新创业竞赛补用户需求、可持续路径和团队成长，教育类竞赛强调学习结果及教师复核。所有赛版追溯到同一版本与同一组真实证据，不为单项赛事制造功能或数据。

可争取的差异来自长期个人证据、资料变化后的建议失效管理、从笔头练习到口头表达的连续验证，以及本地可信执行。竞品能否做到相同效果，要通过同任务、同时间、同模型预算的对照实测，不能预先宣称“别人做不出来”。
