# FileMate 后续开发流程 v2

修订日期：2026-10-03。依据用户最新要求：先完成布局、UX动效与图标包装，再固定工程基线，随后串行启动后续开发。本流程替代历史任务顺序，不删除五模块、B2/B3与正式评测要求。

## 固定内容

- 产品：大学生本地优先学习工作台；保留现有LOGO、Source/Artifact/Context、匿名设备隔离与预览确认/撤销机制。
- 视觉：钴蓝 `#2352d3`、深蓝 `#132755`、冰蓝 `#cad9f3`、阅读面板 `#f6f8fe`、文字 `#15264a`、暖金 `#ffda91`。沿用本地中文字体；显示标题36–70px、正文17–20px、辅助14–15px、主要触控区至少44px。alpha.3微调主色和语义色，保持浅底文字对比度至少4.5。
- 布局：9项主要导航＋任务内相关功能＋完整工具查找；连续动作同屏处理，创建配置按需展开，长内容优先阅读。
- 图标：公共导航、首页与知识库采用Tabler线性SVG，静态按需导入；其余专用业务图标按独立任务迁移，LOGO不改。
- 动效：页面短入场、相关导航选中底板、展开反馈、精细指针光感；减少动画时静态，卸载清理，不放宽首屏体积预算。
- 当前整合发布候选为 `1.3.0-alpha.3`（Python包规范写法 `1.3.0a3`），schema以迁移为准，当前v24。历史视觉基线 `UI-2026.10.03-r1`及alpha.1交付证据保留；线上版本与验收结果以最新发布记录为准。

视觉工程冻结与正式 `v1.3.0` 发布分开记录。当前仍有真实研究、远端CI、桌面和网站版本同步依赖；不能通过修改标签把这些依赖写成完成。

## 每张任务卡的执行合同

1. **核对范围**：读取原要求、当前源码、API与执行账本；指定一个可验收结果、允许改动文件和保留的不变量。预先检查磁盘可用空间、依赖位置和端口，隔离安装/构建及浏览器证据目录应预留至少3 GiB；空间不足先迁移已退出进程的自建缓存，保留源码、最终编译包和验收证据。
2. **落实实现**：先复用现役模型/解析/存储/适配层。涉及API、路由、schema或环境变量时同步调用方、文档与合同测试；不重建另一套数据链。
3. **取得当前证据**：修复失败后运行匹配风险的专项，默认运行 `scripts/verify.ps1 -IsolateFrontend`。使用独立合成目录、空凭据或明确本地模型夹具；记录合成、真实、未测和跳过项。
4. **验收可见操作**：对对应编译包检查真实浏览器与HTTP操作、375/768/1024/1440px、键盘与减弱动画；保留截图、异常记录、进程退出码和清理结果。
5. **固定本卡基线**：核对测试期间源码未变，保留源码/依赖/资源清单与哈希；更新交付索引和账本，再进入下一卡。没有提交或部署时如实记录本地冻结。

失败必须留痕；修复后的新候选使用新证据路径。不同快照的通过数不能相加，也不能把上轮截图当本轮验收。真实学习效果需要学生与导师数据，工程夹具不替代研究。

隔离验证结束后记录缓存与服务的实际位置、进程退出和资源清理结果；不把每轮重新生成的依赖长期当成交付物保留。迁移或清理前核对绝对路径属于该任务临时目录，且没有进程使用；不操作用户资料、私有库或凭据。无完整报告的中断运行保持未完成，恢复后使用新证据目录。
