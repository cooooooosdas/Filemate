## 实现范围

1. 单快照读取真实题目、选中原答、最多5条历史与已确认错因。图谱关联验证题目版本、课程成员和融合节点；引用最多3段／6000字，保留原文全局偏移，不猜测页码。
2. 追加业务schema36，保留旧迁移。分析请求、全部输入来源依赖及无正文请求墓碑持久化；恢复备份轮换epoch并中断运行，删除任一输入源清除相关分析正文。
3. 每次授权至多一次模型调用，私有进程20秒总期限，可取消并回收。结构和逐字引用校验成功后才保存Artifact；失败不编造错因、分数、掌握率或成功报告。
4. 服务端／浏览器凭据分别绑定Provider身份。仅精确模型POST接受临时浏览器凭据；GET、采纳、计划及撤销不发送密钥。失败模型记录不触发账号401退出。
5. 一次错答只建议一个短行动；重复错答、逾期或用户确认错因才扩展，最多7项。预览可编辑，确认才原子新增既有StudyPlan，不改写目标、旧计划或完成记录；撤销会拒绝已修改或已完成的目标。
6. 按需加载大字分析、图谱与任务面板。先作答再分析，展示外发数据；历史可回看但陈旧结果不能采纳。手动错因草稿优先，确认区域可键盘聚焦。图谱、今日、学习计划与错题通过真实ID往返。

## 复现

默认保持`FILEMATE_ENABLE_WRONGBOOK_V2=0`、`FILEMATE_ENABLE_WRONGBOOK_AI=0`及`VITE_ENABLE_WRONGBOOK_V2=false`。个人数据读取、取消、删除和导出仍可用；2.0记录不能通过旧入口降级判题。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify.ps1 -IsolateFrontend
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify_wrongbook_learning.ps1 -CheckRecordedEvidence
```

浏览器复现需生成全新绝对目录：通过进程环境提供合成账户密码，再运行`python -m scripts.acceptance.wrongbook_learning_fixture --data-root <新目录>`。将目录写入本卡临时证据目录的`fixture-path.txt`；用同模块的`--provider-port 8039`启动受控供应端。正式`server:app`在8038端口运行，数据根／DB／上传／归档均指向新目录，开启两个Wrongbook开关和课程图谱，设置`LLM_PROVIDER=openai_compatible`、`LLM_BASE_URL=http://127.0.0.1:8039`、合成模型名及合成密钥。Vite在5199端口开启两个前端入口并代理8038；显式设置CORS仅本机地址。然后运行`node scripts/acceptance/wrongbook_learning.mjs`。全部地址必须是loopback，fixture拒绝已有根目录，受控供应端要求合成标记，脚本不接触生产数据。

前端开关分别true／false构建到本卡独立outDir，再用原`check-bundle.mjs`验证，预算仍为143360字节。保存全门禁退出码、构建退出码及实际浏览器结果后，`scripts/verify_wrongbook_learning.ps1 -RecordEvidence`才允许固定源码摘要；旧证据不会自动跟随新源码变成通过。
