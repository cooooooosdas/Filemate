# FileMate 发布与分支策略

> 生效日期：2026-08-09 · 适用于 v1.2 及后续竞赛版本

## 分支模型

- `main` 始终保持可演示、可安装；禁止直接提交未经验证的功能。
- 日常开发使用短生命周期分支：`codex/<主题>`、`feat/<主题>`、`fix/<主题>`、`docs/<主题>`。
- 每个 Pull Request 只承载一个可说明的产品目标，并在合并前同步 API、数据模型、测试和演示说明。
- 紧急修复从最新发布标签创建 `fix/<问题>`，通过相同 CI 后回到 `main`。

## 提交与版本

- 提交遵循 Conventional Commits：`type(scope): 中文简述`。
- `fix` 增加补丁版本，向后兼容功能增加次版本，破坏性变更增加主版本。
- 竞赛演示使用明确标签，例如 `v1.2.0-reliable-foundation`，禁止用无法复现的临时压缩包作为唯一交付物。

## 合并门槛

每个 PR 必须通过 `.github/workflows/ci.yml`：

1. Python 安装和关键路径 Ruff 检查。
2. 全量非 E2E 后端测试。
3. Python sdist 与 wheel 构建。
4. Vue TypeScript 检查和生产构建。

涉及文件写入的变更还必须证明：不覆盖已有文件、失败可回滚、重复调用幂等、撤销可恢复。涉及 AI 输出的变更必须提供固定响应测试，不能把真实 API Key 放入 CI。

## 发布清单

1. 从干净工作树运行 `scripts/verify.ps1`。
2. 更新 `README.md`、API 规范、数据库版本和变更记录。
3. 在无开发缓存的机器或 CI 中安装 wheel 并做启动冒烟测试。
4. 构建桌面安装包并记录 SHA-256。
5. 使用匿名样例完成 3 分钟演示脚本，确认无密钥、个人文件路径和隐私数据。
6. 创建 Git 标签与 GitHub Release，附安装包、校验值、已知问题和回滚方式。

## 工作区治理

- 运行数据仅进入 `.filemate-data/`、`archive/`、`filemate.db*`，全部不打进 Python 包。
- 临时依赖缓存统一进入 `_working/`。
- 根目录历史调试脚本在确认所有权前不自动删除；发布构建只显式包含 `filemate`、`main.py`、`server.py`，避免把它们带入交付物。
- 每两周执行一次文档、测试、运行数据和发布产物核对。
